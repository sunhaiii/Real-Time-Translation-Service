Voice Pipeline Data Flow

When the counselor or the customer speaks → STT → translation → results are sent to both browsers in the same session. TTS is generated only for counselor speech and played on the customer screen. When an utterance ends, the recording is saved to GCS.

sequenceDiagram participant Speaker as Speaker browser
(counselor or customer) participant BE as Backend (WebSocket) participant STT as Google STT participant Gemini as Gemini translation participant TTS as Google TTS participant GCS as GCS (recordings) participant DB as SQLite participant Listener as Listener browser Speaker->>BE: audio_stream (chunk: PCM 16kHz base64, sender, chat_id) Note over BE: Speaker lock check (chunks dropped while the other side is speaking) BE->>STT: Streaming audio STT-->>BE: Interim / final results BE-->>Speaker: transcription (interim → finalizing) BE-->>Listener: transcription (same) BE->>Gemini: Finalized source text Gemini-->>BE: Translated text BE-->>Speaker: translation_complete BE-->>Listener: translation_complete Speaker->>BE: POST /api/chats/:id/messages (saved by the speaker only) BE->>DB: Save chat_messages opt Counselor speech only BE->>TTS: Translated text TTS-->>BE: MP3 base64 BE-->>Listener: tts_audio (played on customer screen when TTS is on) end Note over Speaker,BE: Utterance ends (is_final) BE->>GCS: Upload recording (WAV) BE->>DB: Save chat_audio_segments (gcs_uri)

Note: If server TTS is unavailable, the customer browser's built-in speech synthesis reads the text instead.
